## Decisions not to re-litigate

All in the spec with rationale. The three most likely to look like bugs:

- **`and more →` will not render.** It auto-hides without a 4th project, and there are exactly 3. Correct behaviour. The list page is reachable via the new nav item.
- **Nav order is `Posts / tags / Playground / About`**, not Playground second. `site-nav.html` sorts on `position`; `posts.md` and `tags.md` have none, so anything under 100 lands after them. Getting Playground second would mean editing two more existing files, which the user and I agreed was not worth it. Spec §2 explains this. I stated the wrong order several times during the session before catching it — if the user asks why, this is the reason.
- **Games cannot save progress.** The iframe sandbox deliberately omits `allow-same-origin`. User confirmed no saves needed. Per-project escape hatch is `needs_storage: true`.
